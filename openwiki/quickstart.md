# GSC — Git Security Checker

> Self-learning code audit with 15 plugin detectors, 350+ patterns, and a Deepsec-inspired pipeline.  
> Detects vulnerabilities, remembers patterns, and gets smarter with every project.

## Quick Facts

| Attribute | Value |
|-----------|-------|
| **What it is** | CLI static analysis security tool (SAST) with self-learning |
| **Language** | Python 3.10+ |
| **Detectors** | 15 plugin detectors (GS001–GS016) |
| **Patterns** | 350+ seed patterns across 7 languages |
| **Precision** | 73% (104 TP / 38 FP as of v0.7) |
| **Pipeline** | 3 echelons + optional LLM deep analysis (E4) |
| **Storage** | SQLite DB (`~/.hermes/state/gsc_audit.db`) |
| **License** | MIT |
| **Required runtime** | ripgrep 13+ (binary, not pip) |

## Quick Start

```bash
# Prerequisites
brew install ripgrep      # macOS
sudo apt install ripgrep  # Linux

# Clone and install
git clone https://github.com/poliakarmai/gsc.git
cd gsc
pip install -e .

# Initialize and scan
gsc doctor                # Verify environment
gsc init                  # Initialize .gsc/ config
gsc scan .                # Full audit
```

## Architecture Overview

GSC uses a Deepsec-inspired pipeline:

```
Scan  →  Revalidate  →  Export
 │           │              │
 ▼           ▼              ▼
candidates → findings → TP/FP/Fixed → JSON / Obsidian / SARIF
```

The scan runs in **3 echelons** plus optional LLM analysis:

1. **E1 — Source-driven** (precise): grep patterns + precise-tier detectors (GS001, GS004, GS005, GS010, GS011, GS014)
2. **E2 — Security** (normal): regex patterns + normal-tier detectors (GS002, GS003, GS007, GS008, GS009, GS012, GS013)
3. **E3 — Adversarial** (noisy): semantic patterns + noisy-tier detector (GS015)
4. **E4 — LLM Deep Analysis** (optional, `--deep`): validates findings via OpenRouter (DeepSeek default)

Post-filtering: docstring/comment filter, inline suppression (`gsc:ignore`), framework-aware AST filter, reachability analysis (opt-in).

See [Architecture](architecture/) for the full pipeline and data flow.

## Detectors (GS001–GS016)

| Rule | Tier | Severity | What it catches |
|------|------|----------|-----------------|
| GS001 | precise | CRITICAL | Hardcoded secrets (API keys, JWT, tokens, connection strings) |
| GS002 | normal | HIGH | World-readable sensitive files (.pem, .key, .env) |
| GS003 | normal | LOW | Debug code left in production (print, console.log) |
| GS004 | precise | HIGH | Dangerous subprocess (shell=True, os.system, eval, exec) |
| GS005 | precise | CRITICAL | SQL injection (f-strings, raw SQL, ORM interpolation) |
| GS007 | normal | HIGH | IDOR — missing auth/ownership checks |
| GS008 | normal | LOW | Dead code — constants/feature flags declared but never used |
| GS009 | normal | HIGH | Supply chain (npm/PyPI/Go/MCP/editor extensions) |
| GS010 | precise | CRITICAL | Weak SSH config (PermitRootLogin, PasswordAuth, etc.) |
| GS011 | precise | CRITICAL | JWT vulnerabilities (alg:none, verify=False, hardcoded secrets) |
| GS012 | normal | HIGH | Mass Assignment (Django, FastAPI, Rails, GraphQL) |
| GS013 | normal | HIGH | GraphQL security (introspection, depth, error disclosure) |
| GS014 | precise | HIGH | Credential exposure (SAM, DPAPI, unattend.xml, sudoers) |
| GS015 | noisy | INFO | Entry-point coverage (all HTTP handlers) |
| GS016 | normal | HIGH | Linux privilege escalation vectors |

See [Detectors](detectors/) for detailed descriptions, detection logic, and pattern storage.

## Key Workflows

- **[Full Audit Workflow](workflows/)**: init → scan → triage → revalidate → fix → report
- **Self-Learning Loop**: findings confirmed as TP create new patterns → future scans detect more
- **CI/CD Integration**: GitHub Action (`action.yml`), pre-commit hook, Helm CronJob
- **Collector Pipeline**: Scrapy spider + lightweight collector scrape NVD/GitHub/HackerOne for patterns
- **GitHub Dorks**: `gsc_github_dorks.py` searches public repos for exposed secrets

## Testing

Corpus tests validate detector behavior against known-good and known-vulnerable code samples.  
8 tests covering SQL injection, hardcoded secrets, unsafe pickle, eval(), world-readable files, clean code (false positive check), and more.

See [Testing](testing/) for test structure and how to add new tests.
