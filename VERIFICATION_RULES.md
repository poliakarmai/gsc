# VERIFICATION_RULES.md — правила верификации findings

> Единый слой правил верификации (по статье «Траблшутинг ИИ-багхантинга», БАСТИОН).
> Принцип: **находку проверяет НЕ тот агент, что её нашёл.** Обнаружение — recall,
> верификация — precision. Бутылочное горлышко сдвинуто с «поиска» на «доказательство».
>
> Этот документ — чек-лист, который судья/верификатор обязан прогнать перед
> приёмкой finding. Рядом с `POF_PARSER_CONTRACT.md` и `gsc_recon/RECON_CONTRACT.md`.

## Три слоя верификации (маппинг на GSC)

| Слой (статья) | GSC |
|---|---|
| **Rules** — жёсткие условия в промпте | этот документ + детекторы + Blocking Engine |
| **RAG** — память об ошибках | self-learning (авто-деактивация <30% TP) + fingerprint + audit-trail |
| **MCP** — активная проверка | PoC Auto-Generation + Proof-of-Fix + runtime validator + sandbox |

Ключевая ловушка из статьи: **правила сжимаются суммаризацией в длинных сессиях.**
Поэтому правила вынесены сюда как фиксированный артефакт, а не в системный промпт.

## Правила по классам (обязательное доказательство)

Правило: признак ≠ уязвимость. Для каждого класса есть минимум, без которого finding
не валиден, и типовой FP-паттерн, который надо исключить первым.

| Класс | Минимум для валидности | Типовой FP (отсеять) |
|---|---|---|
| **SQLi** | time-based (sleep/delay) или error-based (раскрытие SQL) | 500 на одинарную кавычку ≠ SQLi |
| **XSS** | пейлоад исполнился (headless/sandbox) | `<script>` отразился, но заблокирован CSP/nonce |
| **SSRF** | OOB-взаимодействие (callback) или чтение internal | параметр «похож на URL» без подтверждения |
| **SSTI** | исполнение шаблона (`{{7*7}}` → 49) | отражение синтаксиса без evaluation |
| **IDOR/BOLA** | доступ к ЧУЖОМУ объекту (не своему) | 200 на собственный ресурс |
| **Directory listing** | открытый не-публичный путь | публичная CDN-папка |
| **Secrets** | действующий ключ с реальным доступом | отозванный/публичный (DaData) токен |
| **Info disclosure** | данные недоступны в открытых источниках | ПДН из открытого раздела/тестовый сегмент |
| **CSRF** | реальное срабатывание на чувствительном действии | нет токена, но и действия нет |
| **Upload** | исполнение/обход валидации подтверждён | файл загрузился, но не исполнился |

## FP-классы (детерминированный авто-отсев)

Следующие сигналы должны понижать/снимать severity автоматически (детерминированно,
без LLM), ещё до судьи:

1. **CSP блокирует** → XSS без `unsafe-inline`/`unsafe-eval` — не exploit (max LOW).
2. **CDN-хост** (CloudFront, Fastly, Cloudflare, Akamai, S3/GCS static) → directory
   listing / info disclosure — не finding.
3. **Отозванный/публичный секрет** → не finding (проверка revoke-статуса/allowlist).
4. **Редирект-петля/пустой баннер** → не «server misconfig».
5. **Данные из открытого источника** → не утечка.

## Чек-лист судьи (обязательный)

Перед PASS судья обязан проверить (помимо инвариантов кода):

- [ ] finding имеет **доказательство** (PoC/runtime/OOB), а не только признак;
- [ ] PoC **прогнан** в sandbox (runtime validator / proof-of-fix), а не только прочитан код;
- [ ] проверка выполнена **в новой сессии** (не тем агентом, что нашёл);
- [ ] исключены FP-классы (таблица выше) для данного класса;
- [ ] severity не завышена (CSP/CDN/revoked — понижены);
- [ ] проверены **реальные edge-case входы**, не только зелёные тесты.
