# Contributing to GSC

Спасибо за интерес к Git Security Checker! Этот документ описывает правила участия.

## Лицензионное соглашение (CLA)

**Внося вклад в этот проект, вы соглашаетесь с следующим:**

1. Вы предоставляете Алексею Полякову (armyanao@gmail.com) бессрочное, безотзывное, всемирное, безвозмездное право использовать, модифицировать, распространять и сублицензировать ваш вклад под [Apache License 2.0](LICENSE) и/или коммерческой лицензией ([COMMERCIAL.md](COMMERCIAL.md)).

2. Вы подтверждаете, что:
   - Ваш вклад является вашей оригинальной работой
   - Вы имеете право передать права на вклад
   - Вклад не нарушает права третьих лиц

3. CLA вступает в силу в момент открытия Pull Request. Создавая PR, вы автоматически принимаете условия CLA.

**Почему это важно:** GSC использует модель dual license — весь исходный код под [Apache License 2.0](LICENSE), а коммерческая лицензия ([COMMERCIAL.md](COMMERCIAL.md)) требуется только для конкурирующего SaaS-предложения. Единый правообладатель необходим для возможности двойного лицензирования.

## Как внести вклад

### Баги и фичи-реквесты

- Открывайте Issue с шаблоном: проблема → шаги воспроизведения → ожидаемое поведение
- Для фича-реквестов: проблема → предлагаемое решение → почему это важно

### Pull Requests

1. Форкните репозиторий
2. Создайте ветку: `fix/description` или `feat/description`
3. Внесите изменения, добавьте тесты
4. Убедитесь что `python3 tests/test_corpus.py` проходит
5. Откройте PR в `master`

### Требования к коду

- **Тесты обязательны** для новых детекторов и фич
- **Коммиты атомарные** — одна логическая единица на коммит
- **Сообщения на русском** — `feat(scope): описание`
- **Не ломать calibration** — 17/17 тестов должны проходить

### Процесс ревью

1. Автоматическая проверка CI: тесты + линтер
2. Ревью мейнтейнера (Поляков Алексей)
3. Вливание в `master`
