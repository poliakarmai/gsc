# DETECTOR BRIEF — GS034

## 1. Состояние

Детектор GS034 нацелен на выявление npm supply chain атак (ChainDrop) и содержит 20 паттернов для package.json и 6 для JS-файлов. Основные проблемы:

- **Широкие regex-паттерны** с низким порогом срабатывания (например, `token_collector` с confidence 0.70)
- **Отсутствие контекстных фильтров** — нет проверки на легитимность (devDependencies, известные библиотеки, тестовые файлы)
- **Нет проверки на "стандартные" паттерны** — например, `preinstall` с `node` может быть легитимным в некоторых пакетах
- **Нет анализа структуры package.json** — не проверяется, является ли файл реальным манифестом пакета или частью тестов/фикстур

## 2. FP root-cause (по группам)

### Группа A: Легитимные lifecycle-скрипты
- **Root-cause**: Паттерны `preinstall_script`, `postinstall_script`, `install_script` срабатывают на любые команды `node`, `npm`, `python` и т.д. в lifecycle-скриптах. Многие легитимные пакеты используют `preinstall`/`postinstall` для сборки, генерации кода, установки зависимостей.
- **Примеры FP**: пакеты с `"preinstall": "node scripts/build.js"`, `"postinstall": "node scripts/postinstall.js"` — это стандартная практика.

### Группа B: Легитимные имена файлов в зависимостях
- **Root-cause**: Паттерны `setup_mjs_stager`, `infostealer_payload` срабатывают на имена файлов (`setup.mjs`, `loader.mjs`, `Math_Symbol.js`), которые могут встречаться в легитимных пакетах (например, `setup.mjs` — стандартный файл для настройки окружения).
- **Примеры FP**: пакет `@angular/cli` содержит `setup.mjs` для инициализации проекта; `math-symbol.js` — легитимная библиотека для математических символов.

### Группа C: Легитимные обращения к API и env
- **Root-cause**: Паттерн `token_collector` срабатывает на любой `process.env` (кроме исключений), что ложно срабатывает на легитимный код, читающий переменные окружения (например, `process.env.PORT`, `process.env.DB_HOST`).
- **Root-cause**: Паттерн `env_dump_all` срабатывает на `Object.keys(process.env)` — это может быть легитимная отладка или логирование.

### Группа D: Легитимные обращения к файлам
- **Root-cause**: Паттерн `file_exfiltrator` срабатывает на `readFileSync` с путями, содержащими `.env`, `config.json` — это может быть легитимная загрузка конфигурации.
- **Примеры FP**: `readFileSync('.env')` — стандартная практика для загрузки переменных окружения (dotenv).

### Группа E: Легитимные обращения к GitHub API
- **Root-cause**: Паттерн `github_exfil_api` срабатывает на `fetch` к `api.github.com` с `Authorization` — это может быть легитимная интеграция (например, CI/CD, обновление зависимостей).

### Группа F: Легитимные обфусцированные строки
- **Root-cause**: Паттерны `obfuscated_js`, `encoded_payload` срабатывают на `atob`/`Buffer.from` с длинными base64-строками — это может быть легитимная работа с бинарными данными, токенами JWT, сертификатами.

### Группа G: Легитимные зависимости с похожими именами
- **Root-cause**: Паттерн `typo_squatting` срабатывает на имена вида `@scope/utils-extra`, `helper-core` — это может быть легитимный пакет, а не typo-squatting.

## 4. Требует pro-проверки

1. **Список известных легитимных пакетов** — для фильтра `_is_known_legit_file` и `_is_known_typo_squat` нужен актуальный список из npm registry (или статический список топ-1000 пакетов). Flash-гипотеза: список должен быть статическим и обновляться раз в квартал.

2. **Порог для `token_collector`** — flash-гипотеза: исключение `process.env.PORT`, `process.env.HOST` и т.д. может пропустить TP, если злоумышленник использует стандартные имена переменных. Нужна pro-проверка на реальных TP-примерах.

3. **Декодирование base64** — flash-гипотеза: проверка на читаемый текст может быть обманута злоумышленником (например, base64-кодированный JavaScript с комментариями). Нужна pro-проверка на реальных TP-примерах.

4. **Контекст для `env_dump_all`** — flash-гипотеза: проверка на `console.log` может быть обманута, если злоумышленник использует `console.log` для отладки перед отправкой. Нужна pro-проверка.

5. **Порог для `file_exfiltrator`** — flash-гипотеза: проверка на отправку данных (fetch/http) может пропустить TP, если злоумышленник использует `fs.writeFileSync` для записи в другой файл. Нужна pro-проверка.
