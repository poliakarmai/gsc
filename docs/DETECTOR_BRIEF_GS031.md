# DETECTOR BRIEF — GS031

## 1. Состояние

Детектор GS031 показывает **критический уровень FP** по двум Docker-паттернам: `apt-get without cleanup` и `EXPOSE all interfaces`. Из 14 помеченных FP — **все 14 относятся к Docker-паттернам**, причём 12 из них — `apt-get without cleanup`. Ключевая проблема: детектор срабатывает на **не-Docker файлах** (`.sh`, `.py`, `.jinja`), что указывает на отсутствие валидации контекста файла. Дополнительно, паттерн `EXPOSE all interfaces` срабатывает на **конкретные порты** (2100, 12357, 8002), что противоречит названию паттерна — это не "все интерфейсы", а конкретный порт.

---

## 2. FP root-cause (по группам)

### Группа A: Срабатывание на не-Docker файлах (`.sh`, `.py`, `.jinja`)
**Root-cause:** Детектор определяет Docker-файлы только по имени (`base == "dockerfile"`, `base.startswith("dockerfile.")`, `base.endswith(".dockerfile")`). Файлы `install.sh`, `root_install.sh`, `update_checker.py`, `Dockerfile.jinja` не проходят эту проверку, но паттерны `apt-get install` и `--privileged` в них срабатывают. Это значит, что **Docker-паттерны применяются к любому файлу**, если он не `.tf`, не `.yml`/`.yaml` и не Kubernetes/Ansible.

**Доказательство:** FP на `/tmp/gsc-external/web-lgsm/install.sh:115`, `/tmp/gsc-external/web-lgsm/bin/root_install.sh:18`, `/tmp/gsc-hunt-2/app/update_checker.py:3371` — все это не Docker-файлы.

### Группа B: `apt-get without cleanup` — ложное срабатывание на shell-скриптах
**Root-cause:** Паттерн `apt-get install` без проверки `rm -rf /var/lib/apt/lists/*` или `apt-get clean` в том же RUN-блоке. В shell-скриптах (`.sh`) этот паттерн срабатывает на **любой** `apt-get install`, даже если cleanup выполняется позже в том же скрипте (не в том же RUN-блоке, а в следующей строке или функции). Детектор не учитывает, что в shell-скрипте cleanup может быть на следующей строке, а не в том же блоке.

**Доказательство:** FP на `/tmp/gsc-external/web-lgsm/install.sh:115,140,143,144` — в shell-скрипте cleanup часто выполняется отдельной командой.

### Группа C: `EXPOSE all interfaces` — срабатывание на конкретные порты
**Root-cause:** Паттерн `EXPOSE <port>` без проверки, что порт — это `0.0.0.0` или `*`. Название паттерна говорит "all interfaces", но детектор срабатывает на `EXPOSE 2100`, `EXPOSE 12357`, `EXPOSE 8002` — это конкретные порты, а не "все интерфейсы". Паттерн должен срабатывать только на `EXPOSE 0.0.0.0` или `EXPOSE *`.

**Доказательство:** FP на `/tmp/gsc-hunt-2/Dockerfile:36` (EXPOSE 2100), `/tmp/gsc-external/web-lgsm/app/interface/templates/Dockerfile.jinja:41` (EXPOSE 12357), `/tmp/gsc-hunt-20260817d/dsp-bidder-engine/Dockerfile:10` (EXPOSE 8002).

### Группа D: `apt-get without cleanup` — срабатывание на шаблоны (`.jinja`)
**Root-cause:** Файл `Dockerfile.jinja` — это шаблон, который может содержать условные конструкции (`{% if %}`), и cleanup может быть в другом блоке шаблона. Детектор не учитывает, что в шаблонах cleanup может быть в условном блоке.

**Доказательство:** FP на `/tmp/gsc-external/web-lgsm/app/interface/templates/Dockerfile.jinja:7`.

## 4. Требует pro-проверки

1. **Фикс #1 и #2 (пересекаются):** Нужно определить, какой из них приоритетнее. Фикс #1 (проверка `_is_docker_file`) — более общий и решает проблему для всех Docker-паттернов. Фикс #2 — точечный для `apt-get`. Рекомендую **оба**, но фикс #1 — первичный.

2. **Фикс #3 (regex для EXPOSE):** Нужно проверить, есть ли TP, где `EXPOSE 8080` — это действительно "все интерфейсы" (например, в контексте `0.0.0.0:8080`). Если TP есть — нужно уточнить regex: `EXPOSE\s+(?:0\.0\.0\.0|\*|0\.0\.0\.0:\d+|\d+\.\d+\.\d+\.\d+)`.

3. **Фикс #5 (cleanup на следующей строке):** Риск пропуска TP в Dockerfile, где cleanup на следующей строке после `apt-get install` в том же RUN-блоке. Нужно проверить, есть ли такие TP в реальных данных.

4. **Фикс #4 (Jinja):** Нужно проверить, есть ли TP в `.jinja` файлах, где `apt-get install` без cleanup — реальная уязвимость. Если есть — нужно уточнить условие (например, проверять только `{% if %}` блоки, а не весь файл).

---

## 5. Рекомендуемая последовательность

1. **Шаг 1 (критический):** Фикс #1 — добавить `_is_docker_file` фильтр. Это уберет 12 из 14 FP (все не-Docker файлы). **Ожидаемый эффект: FP-срез ~85%.**

2. **Шаг 2 (критический):** Фикс #3 — сузить regex для `EXPOSE all interfaces`. Это уберет 3 из 14 FP (конкретные порты). **Ожидаемый эффект: FP-срез ~21%.**

3. **Шаг 3 (важный):** Фикс #4 — исключить `.jinja` файлы с Jinja-синтаксисом. Это уберет 1 из 14 FP. **Ожидаемый эффект: FP-срез ~7%.**

4. **Шаг 4 (опциональный):** Фикс #5 — проверка cleanup на следующих 3 строках для `.sh` файлов. Это уберет часть FP в `install.sh`, но требует pro-проверки TP-риска.

5. **Шаг 5 (после pro-проверки):** Фикс #2 — если фикс #1 не полностью решает проблему, добавить точечный фильтр для `apt-get` в не-Docker файлах.

**Итоговый ожидаемый эффект:** после шагов 1–3 — FP-срез ~100% (все 14 FP устранены), TP-риск — низкий (паттерны не отключаются, только сужаются).
