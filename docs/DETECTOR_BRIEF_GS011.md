# DETECTOR BRIEF — GS011

## 1. Состояние

Детектор GS011 имеет **4 группы паттернов**:

| Группа | Паттерн | Назначение | Основной шум |
|---|---|---|---|
| `JWT_SECRET_PATTERNS` | 3 regex | Хардкод JWT-секретов | `Potential JWT signing secret (short)` — самый шумный |
| `JWT_ALG_PATTERNS` | 4 regex | Уязвимости алгоритмов | `jwt.decode()` LOW — срабатывает на легитимные вызовы |
| `JWT_LIB_IMPORTS` | 1 regex | Контекст использования JWT | — |

**Ключевая проблема**: паттерны слишком широкие и не учитывают:
- контекст (Django settings, captcha-ключи, тестовые данные);
- структуру вызова `jwt.decode()` (позиционные аргументы, `options`);
- семантику имён переменных (`KEY = "csrftoken"` — это не JWT-секрет).

---

## 2. FP root-cause (по группам)

### Группа A: `Potential JWT signing secret (short)` — ложные срабатывания на не-JWT секреты

**Root-cause**: Паттерн `(?:secret|SECRET)_?(?:key|KEY)\s*[:=]\s*['"]([^'"]{1,64})['"]` слишком общий. Он ловит:
- **Django SECRET_KEY** (`settings.py:23` — `'+=y(#0#l...'`) — это не JWT-секрет, а общий секрет Django;
- **Google reCAPTCHA secret keys** (`captcha.py:59,108` — `'0x000000...'`, `'6LeIxAcT...'`) — это ключи API, не JWT;
- **Тестовые/примерные значения** (`'foo'` в `example/ApiKey/settings.py`, `scripts/makemigrations.py`) — не покрыты фильтром placeholder'ов.

**Дополнительно**: фильтр `skip` не включает `'foo'`, `'test'`, `'dummy'`, `'0x'` (hex-префикс).

---

### Группа B: `JWT decode() — verify signature is explicitly enabled?` (LOW) — ложные срабатывания на легитимные вызовы

**Root-cause**: Паттерн `jwt\.decode\s*\([^)]*\)` срабатывает на **любой** вызов `jwt.decode()`, включая:
- вызовы с `algorithms=["HS256"]` (подпись проверяется);
- вызовы с `options={"verify_signature": True}` (явная проверка);
- вызовы с позиционным аргументом `key` (например, `jwt.decode(token, self.secret, algorithms=["HS256"])`).

**Ключевой дефект**: паттерн не проверяет **отсутствие** `verify=False` или `options={'verify_signature': False}`. Он срабатывает на все вызовы, даже безопасные.

---

### Группа C: `Weak JWT HS256 secret (<256 bits)` — ложные срабатывания на не-JWT константы

**Root-cause**: Паттерн `(?:SECRET|secret|KEY|key)\s*[:=]\s*['"]([\w\-]{1,31})['"]` ловит:
- **`KEY = "csrftoken"`** (`oauth.py:18`) — это имя cookie Django, не JWT-секрет;
- **`KEY = "some_key"`** — общие ключи, не связанные с JWT.

**Проблема**: паттерн не требует контекста JWT (импорт, `jwt.` префикс, `JWT_` в имени).

---

### Группа D: `Hardcoded JWT secret via config dict-assignment` — TP, но есть риск FP

**Root-cause**: Паттерн `(?:config|CONFIG)\s*\[...\]` срабатывает на `app.config['JWT_SECRET_KEY']`, но также может сработать на:
- `config['SECRET_KEY']` (без `JWT_` префикса) — это может быть общий секрет приложения;
- `config['API_KEY']` — не JWT.

**Риск**: паттерн требует `JWT_` в имени, но `(?:JWT_|JWT)?` — опционально, поэтому `config['SECRET_KEY']` тоже попадёт.

## 3. Precision-фиксы

| # | Root-cause | Фикс | FP-срез | TP-риск |

| 1 | **A**: Django SECRET_KEY | Добавить фильтр: если имя переменной `SECRET_KEY` и файл — `settings.py` / `settings/*.py`, и значение содержит спецсимволы (`+=`, `#`, `!`, `@`), то **skip** (это Django-генератор, не JWT). ## 4. Требует pro-проверки

1. **Фикс #4 (негативный regex для `jwt.decode`)** — сложный regex с lookahead. Нужно протестировать на:
   - `jwt.decode(token, key, algorithms=["HS256"])` — должен **не** сработать;
   - `jwt.decode(token, key, options={"verify_signature": False})` — должен сработать;
   - `jwt.decode(token, key)` — должен сработать (нет явной проверки).

2. **Фикс #7 (контекст JWT для weak secret)** — риск пропуска TP: если JWT-секрет объявлен в файле без импорта JWT (например, в `config.py`, который импортируется в `auth.py`). Нужно проверить на реальных проектах.

3. **Фикс #1 (Django settings)** — риск: если разработчик хранит JWT-секрет в `settings.py` как `JWT_SECRET_KEY`, фильтр не должен его пропускать. Нужно уточнить условие: skip только для `SECRET_KEY` (без `JWT_`).

4. **Фикс #6 (`_is_symbolic_constant`)** — нужно определить порог: какие значения считать «символическими константами» (длина, наличие спецсимволов, регистр). Предлагаю: длина < 16, нет спецсимволов, не base64.
