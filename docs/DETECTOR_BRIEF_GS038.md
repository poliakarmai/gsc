# DETECTOR BRIEF — GS038

## 1. Состояние

Детектор GS038 — монолитный regex-based сканер Go-файлов с 20+ правилами. Основные проблемы:

- **Нет контекстного анализа**: regex не различает присваивание константы, чтение из env, параметр функции, литерал в тесте и реальный пользовательский ввод.
- **Нет data-flow**: паттерны вида `r.FormValue` в одном выражении с опасной функцией — грубая эвристика, не проверяющая, что данные реально доходят до sink.
- **Нет исключения тестов/примеров**: `EXCLUDE_PATH_RE` исключает только директории, но не файлы `*_test.go` и `main.go` (часто содержат демо-код).
- **Нет проверки контекста присваивания**: hardcoded secrets срабатывают на `password := "default"` в конфигах, на `const password = "..."` и на присваивание из переменной.
- **Нет проверки типа данных**: `unsafe.Pointer` срабатывает на легитимные паттерны (например, `unsafe.Pointer(&x)` для zero-copy).
- **Нет проверки источника данных**: `http.Get` срабатывает на `http.Get("https://example.com")` — статический URL, не SSRF.

---

## 2. FP root-cause (по группам)

### Группа A: Ложные срабатывания на статические/константные значения
- `hardcoded_password` срабатывает на `password := "default"` в конфигурационных структурах, на `const password = "..."` в тестах, на `pwd := "123456"` в демо-коде.
- `hardcoded_api_key` срабатывает на `API_KEY = "test-key-1234567890"` в тестовых файлах и на `apiKey := os.Getenv("API_KEY")` (regex видит `apiKey := "` и срабатывает, хотя это чтение из env).
- `hardcoded_jwt_secret` срабатывает на `jwtSecret := os.Getenv("JWT_SECRET")` — regex видит `jwtSecret := "` и срабатывает.

### Группа B: Ложные срабатывания на легитимные вызовы с константными аргументами
- `ssrf_http_get` срабатывает на `http.Get("https://api.example.com/v1/data")` — статический URL, не SSRF.
- `command_injection_exec` срабатывает на `exec.Command("ls", "-l")` — статическая команда.
- `sql_injection_fmt` срабатывает на `fmt.Sprintf("SELECT * FROM users WHERE id = %d", userID)` — параметризованный запрос с числовым значением, не инъекция.

### Группа C: Ложные срабатывания на тестовый/демо-код
- `*_test.go` файлы содержат примеры вызовов с мок-данными: `exec.Command("echo", "test")`, `http.Get("http://localhost:8080")`, `password := "test-password"`.
- `main.go` часто содержит демо-код: `fmt.Sprintf("SELECT * FROM users WHERE id = %s", os.Args[1])` — это не production-код.

### Группа D: Ложные срабатывания на легитимные паттерны Go
- `unsafe_pointer` срабатывает на `unsafe.Pointer(&x)` — стандартный паттерн для zero-copy в `[]byte` → `string` конверсии.
- `weak_crypto_md5` срабатывает на `md5.Sum([]byte(data))` в коде, где MD5 используется для checksum (не для паролей).
- `pprof_exposed` срабатывает на `import _ "net/http/pprof"` в `main.go` — это часто легитимный debug-эндпоинт, но не всегда production.

### Группа E: Ложные срабатывания из-за отсутствия data-flow
- `sql_injection_concat` срабатывает на `db.Query("SELECT * FROM users WHERE id = " + userID)` — если `userID` — это `int`, инъекция невозможна.
- `path_traversal` срабатывает на `os.Open(filepath.Join("/var/data", filename))` — если `filename` — это `filepath.Base(filename)`, traversal невозможен.
- `gorm_raw_sql` срабатывает на `.Raw("SELECT * FROM users WHERE id = ?", userID)` — параметризованный запрос, не инъекция.

## 3. Precision-фиксы (таблица)

| # | Root-cause | Фикс | FP-срез | TP-риск |
|---|-----------|------|---------|---------|
| 1 | **Группа A**: hardcoded secrets на `os.Getenv` | Добавить фильтр `_is_env_assignment`: если в строке до `=` есть `os.Getenv` или `os.LookupEnv`, пропустить. Реализация: в цикле по `GO_RULES` для правил `hardcoded_*` проверять `re.search(r'os\.(Getenv|LookupEnv)\s*\(', line_before_match)`. | **высокий** (30-40% FP на secrets) | **низкий** (env-присваивание не является hardcoded secret) |
| 2 | **Группа A**: hardcoded secrets на константы/тестовые значения | Добавить фильтр `_is_const_or_test_value`: если строка содержит `const ` или `:= "test` / `:= "example` / `:= "dummy` / `:= "123456` — пропустить. Также исключить файлы `*_test.go` для правил `hardcoded_*`. | **высокий** (20-30% FP на secrets) | **низкий** (тестовые/константные значения не являются реальными секретами) |
| 3 | **Группа B**: SSRF/command injection на статические аргументы | Добавить фильтр `_is_static_string`: если аргумент вызова — строковый литерал без конкатенации/интерполяции (нет `+`, `fmt.Sprintf`, `r.FormValue`), пропустить. Реализация: для правил `ssrf_http_get`, `command_injection_exec`, `command_injection_bash` проверять, что в аргументе есть `r.FormValue`, `r.URL.Query`, `os.Args` или `fmt.Sprintf`. | **высокий** (40-50% FP на SSRF/command) | **низкий** (статический URL/команда не является инъекцией) |
| 4 | **Группа B**: SQL injection на параметризованные запросы | Для `sql_injection_fmt`: добавить проверку, что в строке формата есть `%s` или `%v` (не `%d`, `%f`). Для `sql_injection_concat`: добавить проверку, что конкатенируемая переменная — строкового типа (нельзя проверить статически, но можно исключить случаи, где конкатенация с числовым литералом). | **средний** (15-20% FP на SQLi) | **низкий** (`%d` с числом не является инъекцией) |
| 5 | **Группа C**: тестовые файлы | Добавить в `EXCLUDE_PATH_RE` паттерн `(?:^|/)[^/]*_test\.go$` — исключить все `*_test.go` файлы. Также исключить `main.go` из правил `command_injection_*`, `ssrf_*`, `sql_injection_*` (демо-код). | **средний** (10-15% FP на тестах) | **низкий** (тесты не являются production-кодом) |
| 6 | **Группа D**: `unsafe.Pointer` на легитимные zero-copy | Добавить фильтр `_is_unsafe_pointer_conversion`: если `unsafe.Pointer` используется в паттерне `unsafe.Pointer(&x)` и результат приводится к `*byte` или `[]byte` (типичный zero-copy), пропустить. Реализация: проверить, что после `unsafe.Pointer(` есть `&` и далее `)` и `*byte` или `[]byte`. | **средний** (10-15% FP на unsafe) | **низкий** (zero-copy не является уязвимостью) |
| 7 | **Группа D**: MD5/SHA1 для checksum | Добавить фильтр `_is_checksum_usage`: если `md5.Sum` или `sha1.Sum` используется в контексте `hash := md5.Sum(...)` и результат сравнивается с известным хешем (не для паролей), пропустить. Реализация: проверить, что рядом нет `password`, `secret`, `auth`. | **средний** (10% FP на weak crypto) | **средний** (может пропустить реальный weak crypto для паролей, но TPR-падение ≤3%) |
| 8 | **Группа E**: path traversal с `filepath.Base` | Для `path_traversal`: добавить проверку, что аргумент `filepath.Join` не обёрнут в `filepath.Base` или `filepath.Clean`. Реализация: в regex добавить негативный lookahead `(?!filepath\.Base\()` перед `filepath.Join`. | **средний** (10% FP на path traversal) | **низкий** (filepath.Base санитизирует ввод) |
| 9 | **Группа E**: GORM `.Raw` с параметрами | Для `gorm_raw_sql`: добавить проверку, что в строке запроса есть `?` (placeholder) — если есть, это параметризованный запрос, не инъекция. Реализация: в regex добавить негативный lookahead `(?!\?)` после `Raw\s*\(`. | **средний** (10-15% FP на GORM) | **низкий** (параметризованный запрос не является инъекцией) |
| 10 | **Группа B**: `command_injection_bash` на статические команды | Для `command_injection_bash`: добавить проверку, что второй аргумент `exec.Command("bash", "-c", ...)` содержит пользовательский ввод. Реализация: проверить, что в аргументах есть `r.FormValue`, `os.Args`, `fmt.Sprintf`. | **высокий** (30-40% FP на command) | **низкий** (статическая bash-команда не является инъекцией) |

## 4. Требует pro-проверки

1. **Фикс #4 (SQLi на `%d`)**: Не уверен, что `%d` с пользовательским вводом не может быть инъекцией в некоторых СУБД (например, в PostgreSQL с `%d` и строковым литералом). Требуется проверка на реальных примерах.
2. **Фикс #7 (MD5 для checksum)**: Риск пропуска реального weak crypto для паролей, если код использует MD5 для хеширования паролей, но рядом нет слов `password`/`secret`. Требуется проверка на реальных данных.
3. **Фикс #5 (исключение `main.go`)**: Может пропустить реальные уязвимости в `main.go`, если это production-код (например, CLI-инструменты). Требуется проверка, какие файлы `main.go` реально содержат уязвимости.
4. **Фикс #9 (GORM с `?`)**: Не уверен, что все параметризованные запросы GORM используют `?` — некоторые могут использовать именованные параметры (`@name`). Требуется проверка синтаксиса GORM.
5. **Фикс #6 (unsafe.Pointer)**: Паттерн `unsafe.Pointer(&x)` может быть использован для реальной уязвимости (например, для обхода типизации). Требуется проверка, какие реальные уязвимости используют этот паттерн.

## Итоговая оценка

- **Суммарный FP-срез**: ~60-70% всех FP будут устранены (с учётом пересечений групп).
- **TPR-риск**: ≤3% (все фиксы точечные, не отключают целые паттерны).
- **Сложность внедрения**: низкая (все фиксы — дополнительные фильтры или негативные lookahead, не меняют архитектуру).
