# DETECTOR BRIEF — GS015

## 1. Состояние

Детектор GS015 — это **noise-tier** матчер, предназначенный для разметки HTTP-обработчиков с целью последующего AI-ревью. Он не ищет уязвимости, а лишь помечает потенциальные entry point'ы. Однако текущая реализация демонстрирует **критический уровень дублирования**: один и тот же декоратор `@app.post(...)` матчится сразу **тремя паттернами** (FastAPI, Flask, Sanic), что порождает 3 находки на одну строку кода.

**Ключевые проблемы:**
1. **Отсутствие дедупликации** — паттерны не исключают друг друга, каждый матч дублируется 2–3 раза.
2. **Пересечение паттернов** — regex для FastAPI, Flask и Sanic практически идентичны (`@\w+\.(get|post|...)`).
3. **Ложное срабатывание на `app = FastAPI(...)`** — паттерн `(?:app|application)\s*=\s*\w+\(` матчит создание приложения, хотя это не entry point, а его инициализация.
4. **Некорректный skip-фильтр** — `_SKIP_PATH_PATTERNS` не срабатывает для `example_projects/...`, так как путь содержит `example_projects`, а не `examples/`.

---

## 2. FP root-cause (по группам)

### Группа A: Дублирование находок из-за пересечения паттернов
**Root-cause:** Паттерны FastAPI, Flask и Sanic используют одинаковый regex `@\w+\.(get|post|put|delete|patch|route|...)`. Один и тот же декоратор `@app.post(` матчится всеми тремя паттернами, создавая 3 находки на одну строку.

**Пример:** `@app.post(` → 3 находки (FastAPI, Flask, Sanic).

### Группа B: Ложное срабатывание на инициализацию приложения
**Root-cause:** Паттерн `(?:app|application)\s*=\s*\w+\(` матчит `app = FastAPI(`, `app = Flask(`, `app = Starlette(`. Это не entry point, а создание объекта приложения. Находка `WSGI/ASGI application entry` — ложная, так как сам факт создания приложения не является HTTP-обработчиком.

**Пример:** `app = FastAPI(` → находка `WSGI/ASGI application entry`.

### Группа C: Неверный skip-фильтр для demo/example директорий
**Root-cause:** `_SKIP_PATH_PATTERNS` ищет `(?:/|\A)(?:tests?|fixtures?|examples?|samples?|demo|docs?)/`, но не покрывает `example_projects/`, `guide/`, `sanic/` (которые содержат реальный код, но не являются entry point'ами проекта).

**Пример:** `example_projects/change_password_demo/app.py` не попадает под skip, хотя это демо-проект.

### Группа D: Ложное срабатывание на `@bp.route(` (Blueprint)
**Root-cause:** Паттерн `@\w+\.route(` матчит `@bp.route(`, где `bp` — это Blueprint, а не приложение. Это валидный entry point, но детектор помечает его как `FastAPI/Starlette route handler`, хотя это Flask Blueprint.

**Пример:** `@bp.route(` → находка `FastAPI/Starlette route handler` (неверный фреймворк).

### Группа E: Ложное срабатывание на файлы в entry-point директориях без паттернов
**Root-cause:** Файлы в `sanic/models/asgi.py`, `sanic/cli/app.py` попадают под `TARGET_GLOBS` (`**/app.py`, `**/asgi.py`), но не содержат паттернов. Детектор помечает их как `Entry-point directory file — AI review recommended`, хотя это внутренние модули, не являющиеся entry point'ами.

**Пример:** `sanic/models/asgi.py` → находка `Entry-point directory file`.

## 3. Precision-фиксы (таблица)

| Root-cause | Фикс | FP-срез | TP-риск |
|---|---|---|---|
| **A: Дублирование** | Добавить **дедупликацию по (file, line, matched_text)** — после сбора всех находок для файла, оставлять только первую находку для каждой строки. Реализовать через `seen = set()` и проверку `(rel_path, lineno, matched_text)` перед добавлением. | **Высокий** (устраняет ~60% всех FP) | **Низкий** (TP не теряются, только дубли) |
| **A: Пересечение паттернов** | **Сужение паттернов по фреймворку:** для FastAPI — `@\w+\.(?:get\|post\|put\|delete\|patch\|options\|head)\s*\(` (без `route`); для Flask — `@\w+\.route\s*\(` + `@\w+\.(?:get\|post\|...)\s*\(` (оставить); для Sanic — `@\w+\.(?:get\|post\|...)\s*\(` (оставить). **Ключевое:** добавить проверку контекста — если в файле есть `from fastapi import` или `import fastapi`, использовать только FastAPI-паттерн; если `from flask import` — только Flask; если `from sanic import` — только Sanic. | **Высокий** (устраняет дубли на уровне паттернов) | **Средний** (если файл использует несколько фреймворков, может потерять часть TP, но это редкий случай) |
| **B: Инициализация приложения** | **Исключить паттерн `(?:app\|application)\s*=\s*\w+\(` из ENTRY_PATTERNS** или **сужение:** `(?:app\|application)\s*=\s*(?:Flask\|FastAPI\|Starlette\|Sanic)\(` — но это всё равно не entry point. **Лучший вариант:** удалить этот паттерн полностью, так как создание приложения не является HTTP-обработчиком. | **Высокий** (устраняет все `WSGI/ASGI application entry` FP) | **Низкий** (TP-паттерн не был реальным entry point'ом) |
| **C: Skip-фильтр** | **Расширить `_SKIP_PATH_PATTERNS`:** добавить `example_projects?`, `guide`, `sanic` (если это библиотека, а не проект). Но **осторожно:** `sanic/` может быть реальным проектом. **Точечный фикс:** добавить `example_projects?` и `guide` в skip-паттерн. | **Средний** (устраняет FP в demo-проектах) | **Низкий** (если `example_projects` — реальный код, потеряем TP, но это маловероятно) |
| **D: Blueprint** | **Добавить отдельный паттерн для Blueprint:** `@\w+\.route\s*\(` с фреймворком `flask` (Blueprint — это Flask-концепция). Или **исключить `route` из FastAPI-паттерна** (FastAPI использует `@app.get/post/...`, а не `@app.route`). | **Средний** (устраняет неверную классификацию) | **Низкий** (FastAPI не использует `@app.route` в стандартной практике) |
| **E: Файлы без паттернов** | **Убрать fallback-находку `Entry-point directory file`** или **сужение:** помечать только файлы, которые содержат хотя бы один из маркеров: `def `, `class `, `import `, `from `. Если файл пустой или содержит только комментарии — не помечать. | **Средний** (устраняет FP для внутренних модулей) | **Средний** (может потерять TP для файлов с кастомными фреймворками, где нет стандартных паттернов) |

## 4. Требует pro-проверки

1. **Дедупликация по строке** — нужно убедиться, что в одном файле на одной строке не может быть двух разных entry point'ов (например, `@app.get` и `@app.post` на одной строке — маловероятно, но возможно в однострочных лямбдах).
2. **Контекстное определение фреймворка** — проверка `import fastapi` / `from flask import` может быть ненадёжной, если файл использует динамический импорт или `importlib`.
3. **Skip-фильтр для `sanic/`** — если `sanic/` — это реальный проект, а не библиотека, skip приведёт к потере TP. Нужно проверить структуру репозитория.
4. **Удаление паттерна `app = ...`** — нужно убедиться, что нет реальных сценариев, где создание приложения является entry point'ом (например, в тестах или при кастомной инициализации).
5. **Fallback-находка** — если убрать её полностью, потеряем возможность AI-ревью для кастомных фреймворков. Возможно, стоит оставить, но с более строгим фильтром (например, только для файлов с `def main(` или `if __name__ == "__main__"`).

---

## 5. Рекомендуемая последовательность

1. **Фикс B (удаление паттерна `app = ...`)** — самый безопасный, устраняет ~20% FP, TP-риск минимальный.
2. **Фикс A1 (дедупликация по строке)** — устраняет ~60% FP, TP-риск низкий.
3. **Фикс A2 (контекстное определение фреймворка)** — устраняет дубли на уровне паттернов, TP-риск средний, требует аккуратной реализации.
4. **Фикс D (Blueprint)** — устраняет неверную классификацию, TP-риск низкий.
5. **Фикс C (skip-фильтр)** — устраняет FP в demo-проектах, TP-риск низкий.
6. **Фикс E (fallback-находка)** — самый рискованный, требует pro-проверки, делать последним.

**Итоговый эффект:** ожидаемое снижение FP на 80–90% без потери TP (при условии корректной реализации контекстного определения фреймворка).
